# Link Space Chat 项目需求来源与需求分析 - 演讲要点速查

**创建时间**: 2025年11月

---

## 一、开场 (2-3分钟)

### 核心信息
- **项目**: Link Space Chat - 轻量级跨网络即时消息平台
- **特点**: 零认证、一键启动、临时性、隐私保护
- **今天讲什么**: 需求来源（Task2 URS） + 需求分析（Task3 结构化分析）

---

## 二、需求来源 (Task2) (5-7分钟)

### 2.1 需求收集
- 24份用户问卷
- 目标用户：学生、年轻职场人士
- **三大痛点**:
  1. 传统IM"先加好友再沟通"太繁琐
  2. 不愿暴露私人账号
  3. 临时群聊难删除

### 2.2 核心功能需求（9个）
**房间管理 (REQ-1.x)**:
- 1.1 一键创建房间
- 1.2 生成访问链接（LAN + 公网）
- 1.3 自动数据删除（最后用户离开时清空）

**消息功能 (REQ-2.x)**:
- 2.1 文本消息
- 2.2 Emoji支持
- 2.3 & 2.4 图片/文件分享（5MB限制）
- 2.5 Markdown支持

**用户交互 (REQ-3.x)**:
- 3.1 临时昵称（1-20字符，房间内唯一）
- 3.2 在线用户列表
- 3.3 加载历史消息（最近20条）

### 2.3 非功能需求
- **性能**: 进入房间≤3秒，消息延迟≤1秒
- **安全**: 不收集PII，加密传输，临时存储
- **容量**: 支持至少10并发用户

## 三、需求分析 (Task3) (15-20分钟)

### 3.1 分析方法
- **结构化需求分析**
- **三个维度**: 功能、数据、行为
- **5张核心图表**

---

### 3.2 功能建模 - DFD (6-8分钟)

#### 图表1: DFD-0 (上下文图)
**要点**:
- 系统边界：4个外部实体
  - Host User（主机用户）
  - Participant User（参与用户）
  - Health Probe（健康监控）
  - Ngrok Service（穿透服务）
- **作用**: 明确系统边界和输入输出

#### 图表2: DFD-1 (1级DFD)
**要点**:
- 4个子系统：
  1. 1.0 服务管理（启动、链接生成）
  2. 2.0 会话与认证（加入/离开、昵称验证）
  3. 3.0 消息处理（消息路由）
  4. 4.0 数据初始化（数据库、历史消息）
- 3个数据存储：D1用户、D2房间与成员、D3消息
- **作用**: 展示系统主要功能模块

#### 图表3: DFD-2 (消息处理2级DFD)
**要点**:
- 6个子过程：
  1. 3.1 解析内容类型
  2. 3.2 标准消息处理
  3. 3.3 投票处理
  4. 3.4 文件中转
  5. 3.5 消息渲染与发送
  6. 3.6 P2P与WebRTC处理
- **作用**: 展示消息处理的详细流程

---

### 3.3 数据建模 - E-R图 (4-5分钟)

#### 图表4: E-R图
**要点**:
- **7个核心实体**:
  1. User（用户）
  2. Room（房间）
  3. Message（消息）
  4. Room_Membership（房间成员关系）
  5. Poll（投票）
  6. Poll_Option（投票选项）
  7. Vote（表决）
- **关键关系**:
  - 用户 ↔ 房间：多对多（通过Room_Membership）
  - 消息 → 房间：多对一
  - 投票 → 房间：多对一
- **作用**: 为数据库设计提供蓝图

---

### 3.4 行为建模 - STD (4-5分钟)

#### 图表5: 状态转换图
**要点**:
- **7个状态**:
  1. 开始
  2. 在大厅
  3. 加入中
  4. 聊天中 ⭐（主要状态）
  5. 重连中
  6. 已断开
  7. 结束
- **关键转换**:
  - submit_join: 在大厅 → 加入中
  - join_success: 加入中 → 聊天中
  - network_lost: 聊天中 → 重连中
- **作用**: 指导前端状态管理
