# PPT制作规划（邢天舒负责）

## 一、PPT总体设计

### 1.1 设计原则
1. **简洁明了**: 每页不超过7行文字，避免信息过载
2. **图文并茂**: 使用截图、代码片段、图表增强视觉效果
3. **统一风格**: 使用统一的配色方案和字体
4. **重点突出**: 使用加粗、颜色标记重点内容
5. **专业美观**: 符合学术报告规范

### 1.2 配色方案
- **主色调**: 深蓝色（#1e3a8a）或深灰色（#1f2937）
- **强调色**: 蓝色（#3b82f6）或绿色（#10b981）
- **背景色**: 白色或浅灰色（#f9fafb）
- **文字色**: 深灰色（#111827）或黑色

### 1.3 字体规范
- **标题**: 微软雅黑或Arial，24-32pt，加粗
- **正文**: 微软雅黑或Arial，16-20pt，常规
- **代码**: Consolas或Courier New，14-16pt

### 1.4 PPT结构
- **总页数**: 15-16页
- **封面**: 1页
- **目录**: 1页（可选）
- **正文**: 13-14页
- **总结**: 1页

### 第14页：Debug细节 - PIE模型

#### 内容
```
Debug细节分享 - PIE模型

PIE模型（Execution, Infection, Propagation）：
• Execution（执行）：程序执行过程中发生错误
• Infection（感染）：错误导致程序状态异常
• Propagation（传播）：错误传播到输出，导致可见的bug

调试流程：
1. 定位（Locate）：确定bug的位置
2. 理解（Understand）：理解bug的原因
3. 修复（Fix）：实施修复方案
4. 验证（Verify）：验证修复是否有效

Bug案例：历史记录加载问题

问题：历史消息加载异常，投票数据缺失

PIE分析：
• Program：异步循环错误处理不足
• Input：包含投票消息的大量历史消息
• Environment：高并发环境下数据库查询失败

修复方案：
• 使用Promise.all并行加载
• 添加try-catch错误处理
• 保持消息顺序

[插入修复前后代码对比]
```
