### 2. [Demo演示详细规划](./02-Demo演示详细规划.md)
**负责人**: 邢天舒  
**内容**:对应总体规划7-8
- 代码细节展示（1-1.5分钟）
  - 目标: 展示项目复杂度和代码质量。
  - 核心对象: Join Room (加入房间) 流程。
  - 展示方式: 在IDE或PPT中展示一段连续的、逻辑复杂的代码（>100行），简述其处理了参数校验、房间存在性检查、用户状态更新等逻辑。
- 实际运行演示（2分钟）
  - 目标: 让全班通过MVP (Minimum Viable Product) 体验即时通讯。
  - 步骤:
    1. 生成并展示访问链接/二维码（确保局域网/公网可访问）。
    2. 加入房间: 演示手机/PC端填入昵称进入房间。
    3. 发送消息: 演示文字发送，多用户同时发送。
    4. 交互反馈: 展示消息实时同步的效果。

### 3. [测试过程详细规划](./03-测试过程详细规划.md)
**负责人**: 孙宇轩  
**内容**:对应9-13点
- 测试策略与目录概述
  - 明确非全量测试，而是针对性测试
  - 测试部分的小目录：黑盒n条，白盒n条，debug，维护
- 前端黑盒测试 (0.5分钟)
  - 形式: PPT表格展示。
  - 内容: 列出PC端/移动端适配测试项（输入 -> 预期输出 -> 实际结果 -> Pass/Fail）。
  - 动作: 快速过一遍表格，不进行演示。
- 后端白盒测试 (2-3分钟) (核心重点)
  - 理论应用: 必须明确指出使用了哪种覆盖方法。
  - 模块1：健康维护 -> 采用 语句覆盖 (Statement Coverage)。
  - 模块2：消息流程 -> 采用 判定/分支覆盖 (Branch Coverage)。
  - 模块3：投票过程 -> 采用 路径覆盖 (Path Coverage) 或条件覆盖。
  - 展示代码逻辑流程图与对应的测试路径。
- Debug细节分享（1分钟）
  - 案例：历史记录加载问题
  - 模型：PIE模型 (Execution执行 -> Infection感染 -> Propagation传播)。
  - 流程：复现 -> 定位 -> 修复 -> 验证。
- 软件维护分析 (1分钟)
  - 数据源: Git Commit 历史记录。
  - 分类统计:
    1. 改正性维护 (Corrective) - 修Bug
    2. 适应性维护 (Adaptive) - 环境/库更新
    3. 完善性维护 (Perfective) - 功能优化/重构
    4. 预防性维护 (Preventive) - 文档/注释/预检
