## 图表分类总览

### 一、必须的图表（作业要求）

#### 1. **01-use-case-link-space-chat.drawio** - 用例图 (Use Case Diagram)
- **类型**: 用例图
- **是否必须**: ✅ **必须**
- **状态**: ✅ 已满意，保留
- **描述内容**: 
  - 展示 Link Space Chat 即时聊天系统的所有用例
  - 包含三个主要功能组：
    - **房间管理**：加入房间、查看在线用户列表、查看房间信息、离开房间、输入房间密码
    - **消息功能**：发送消息、回复消息、发送高亮消息、查看历史消息、搜索消息、接收实时消息
    - **创建者专用功能**：设置房间密码、修改房间名称、修改房间密码、修改房间描述、取消房间密码
  - 包含两个参与者：普通用户（Participant）和房间创建者（Room Creator）
  - 展示了用例之间的 include 和 extend 关系

#### 2. **02-domain-class-model.drawio** - 领域类模型 (Domain Class Model)
- **类型**: 类图/领域类模型
- **是否必须**: ✅ **必须**
- **状态**: ✅ 已满意，保留
- **描述内容**:
  - 展示了系统的核心领域类及其关系
  - 包含以下类：
    - **Room**: 房间实体（持久化，存储在SQLite数据库）
    - **Message**: 消息实体（持久化，支持回复和高亮）
    - **RoomState**: 内存中的房间状态管理
    - **RateLimiter**: 频率限制器（内存状态管理）
    - **MessageService**: 业务逻辑服务
  - 展示了类之间的关系和依赖

#### 3. **03-sequence-join-room.drawio** - 序列图：加入房间
- **类型**: 序列图 (Sequence Diagram)
- **是否必须**: ✅ **必须**（核心用例的序列图）
- **状态**: ✅ 已重绘，与代码实现对齐
- **描述内容**:
  - 展示用户加入房间的完整交互流程
  - 参与者：用户、浏览器客户端、Socket.IO Server、Database、RoomState、MessageService
  - 主要步骤：
    1. 用户输入房间ID、昵称、密码
    2. 发送 join_room 事件
    3. 服务器获取房间信息
    4. **检查空房重置**（如果房间存在但在线用户为0，清空消息和密码）
    5. 验证密码（如果房间有密码）
    6. 检查昵称是否占用（通过RoomState）
    7. 确保房间存在（如果不存在则创建）
    8. 加入Socket.IO房间
    9. 添加到RoomState
    10. 获取历史消息
    11. 广播房间信息和在线用户列表
  - 包含错误处理：密码错误/昵称占用的异常流程

#### 4. **04-sequence-send-message.drawio** - 序列图：发送消息
- **类型**: 序列图 (Sequence Diagram)
- **是否必须**: ✅ **必须**（核心用例的序列图）
- **状态**: ✅ 已重绘，包含频率限制、高亮检测等
- **描述内容**:
  - 展示发送消息的详细流程
  - 参与者：用户、浏览器客户端、Socket.IO Server、RateLimiter、MessageService、Database
  - 主要步骤：
    1. 用户输入消息文本
    2. 发送 chat_message 事件
    3. 检查是否在房间中
    4. **频率限制检查**（3秒内最多5条消息）
    5. 保存消息（包含内容类型检测和高亮检测）
    6. 记录消息时间戳
    7. 广播消息给所有用户
  - 展示了高亮检测逻辑：检测 # 开头的文本，自动设置 isHighlighted=true
  - 包含频率限制超限的错误处理

#### 5. **05-sequence-reply-message.drawio** - 序列图：回复消息
- **类型**: 序列图 (Sequence Diagram)
- **是否必须**: ✅ **必须**（核心用例的序列图）
- **状态**: ✅ 已重绘
- **描述内容**:
  - 展示消息回复功能的完整流程
  - 参与者：用户A、用户B、浏览器A、浏览器B、Socket.IO Server、MessageService、Database
  - 主要步骤：
    1. 用户A发送原始消息
    2. 用户B点击/长按消息，选择回复
    3. 显示回复输入框，输入回复内容
    4. 发送包含 parentMessageId 的回复消息
    5. MessageService 保存回复消息到数据库
    6. 广播包含 parentMessageId 的消息给所有用户
    7. 前端根据 parentMessageId 查找父消息并显示回复引用块
  - 展示了回复引用的前端显示逻辑

### 二、可选的加分项图表

#### 6. **06-activity-manage-room-password.drawio** - 活动图：管理房间密码
- **类型**: 活动图 (Activity Diagram)
- **是否必须**: ⭐ **可选加分项**
- **状态**: ✅ 已重绘，与代码逻辑对齐
- **描述内容**:
  - 展示创建者管理房间密码的完整业务流程
  - 主要流程：
    1. 创建者请求修改房间信息
    2. 检查是否在房间中
    3. 检查是否为默认房间（"1"不能设置密码）
    4. 检查是否为房间创建者（权限验证）
    5. 判断是否修改密码
    6. 如果修改密码：设置新密码或移除密码（都会清空聊天记录）
    7. 如果只修改名称/描述：直接更新
    8. 更新数据库
    9. 广播房间信息更新事件
  - 包含多个决策点和错误处理分支

#### 7. **07-state-machine-room.drawio** - 状态机图：房间状态
- **类型**: 状态机图 (State Machine Diagram)
- **是否必须**: ⭐ **可选加分项**
- **状态**: ✅ 已重绘，展示空房重置等状态转换
- **描述内容**:
  - 展示房间对象的状态转换
  - 状态包括：
    - **房间不存在**：系统初始化或房间从未被创建
    - **开放房间（无密码）**：无密码保护，任何用户可加入
    - **密码保护房间**：需要密码才能加入
    - **空房间（待重置）**：所有用户离开后，延迟3分钟清理
  - 转换条件：
    - 系统初始化 → 房间不存在
    - 第一个用户加入 → 开放房间
    - 创建者设置密码 → 密码保护房间
    - 创建者取消密码 → 开放房间
    - 所有用户离开 → 空房间（3分钟后延迟清理）
    - **新用户加入空房间 → 开放房间（重置，清空消息和密码）**
    - 修改密码 → 密码保护房间（清空记录）
    - 延迟清理超时 → 结束状态
